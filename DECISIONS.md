# DECISIONS — решения агента

Здесь записаны решения, которые агент принял сам там, где GDD молчит или противоречит себе (GDD, раздел 0, п. 4).
Решения автора — в `docs/GDD.md`, раздел 22. Формат: дата, решение, почему.

## 2026-10-02 — Этап 0 (фундамент)

| # | Решение | Почему |
|---|---|---|
| D1 | Проект Godot лежит в корне репозитория; в служебных папках (`docs/`, `references/`, `tools/`, `art/`) лежит пустой `.gdignore`. | Так проще CI и сессиям; Godot не импортирует референсы и исходники. |
| D2 | Логика отделена от отображения. `World.step(dt)` двигает всю симуляцию фиксированным шагом 1/60 с. Логика живёт в плоскости этажа: `x` — колонка, `y` — строка ASCII-карты, 1 клетка = 1 м. В 3D: `X = x`, `Z = y`, `Y` — высота. Север (верх карты) — вверху экрана. | Бот-тестировщик может гонять этаж быстрее реального времени без графики; финальная графика подключается без правки логики (GDD 18.3). |
| D3 | Без физического движка в геймплее: коллизии — круг против сетки стен и круг против круга; попадания — геометрические запросы (круг, конус, линия, прямоугольник) по списку сущностей. | Детерминированность, простые тесты, нет сюрпризов физики. Сущностей на этаже десятки, перебор дешёвый. |
| D4 | Свет факелов запекается в текстуру-сетку этажа (4 текселя на метр) с учётом видимости через стены. Динамических OmniLight для факелов нет. | Рендерер Compatibility рисует каждый источник отдельным проходом — на телефоне это дорого; к тому же свет без теней «протекал» бы сквозь стены. |
| D5 | Факелы расставляются автоматически: на стенах, граничащих с полом, детерминированно по хешу клетки, с минимальным шагом; в json этажа можно добавить или запретить факелы. | В легенде ASCII-карты нет символа факела, а расставлять сотни факелов руками незачем. |
| D6 | Юнит-тесты — собственный лёгкий раннер `tests/run_tests.gd` вместо GUT/gdUnit4. | Нет зависимости от аддона и его совместимости с Godot 4.7; запускается одной командой headless и в CI. |
| D7 | Случайность — отдельные детерминированные потоки по назначению (`loot`, `cards`, `reroll`, `combat`, `ai`), seed = хеш(seed забега, номер этажа, имя потока). | Честный рандом из GDD 11.1: перезапуск этажа не перебрасывает лут и карточки. |
| D8 | Камера: перспектива с узким углом обзора, наклон ≈ 55°, без поворота вокруг вертикали (стены идут вдоль краёв экрана, как на карте-референсе). Высота стен 2,2 м; стены между камерой и героем растворяются (срез). | Ракурс совпадает с картой подземелья из референсов и один в один ложится на ASCII-карты. |
| D9 | Язык по умолчанию — язык системы (en/ru/es), иначе английский. | Игрок сразу видит родной язык. |
| D10 | Флаг `gore_enabled` = false. Эффекты крови в MVP не создаются. | Решение автора 13 (кровь — после MVP, с переключателем). |
| D11 | Сборки для ПК — Windows и macOS (без подписи), APK — debug, архитектуры arm64-v8a и x86_64. | Автор тестирует на ПК и в эмуляторе Android; x86_64 нужна, чтобы эмулятор работал быстро. |
| D12 | Расталкивание тел: враги толкают героя сильно (0,9), герой врагов — слабо (0,1); во время уворота герой проходит сквозь врагов. | Пачка в узком проходе реально перекрывает путь (GDD 1, столп «Маршрут»), а уворот — способ проскочить в открытых проходах. |
| D13 | Тап по врагу: выбирается живой враг, ближайший к точке касания на экране (радиус 110 px), в правой половине экрана. Левая половина — джойстик. | Простое и предсказуемое попадание пальцем по мелким целям. |
| D14 | Цифры урона и полоски HP рисуются 2D-слоем поверх 3D (проекция позиции), а не 3D-надписями. | Дешевле на телефоне и всегда читаемо. |
| D15 | Debug-меню показывается в dev-сборках (`depthbound/dev_build=true` в project.godot) — в том числе в release-экспорте для тестов автора. Перед релизом флаг выключается. Тексты debug-меню не локализуются. | Автор тестирует release-сборку; инструмент только для разработки. |
| D16 | Анимации покупаются один раз на риге героя и переиспользуются всеми персонажами Meshy через общую библиотеку `SharedAnims` (`shared/<Clip>`). | У всех ригов Meshy одинаковые имена костей; экономия кредитов. |
| D17 | Оружие мобов (дубина, щит, арбалет) и меч героя собраны из примитивов и крепятся к костям рук. | Мелкие на экране, а генерация каждого стоит 15–21 кредит. Можно заменить моделями Meshy позже. |
| D18 | В правиле «хотя бы одна карточка — характеристика» (GDD 9.4) «Отсрочка» считается характеристикой. | Она стоит в таблице характеристик GDD 9.3. |
| D19 | Сундуки, рычаги, вентили не блокируют движение; решётки (`D`) и решётки-«замки» (`B`) блокируют клетку. | Узкие проходы 2 м не должны затыкаться предметами. |
| D20 | Решётки-«замки» привязываются к пачке из `locks` в json этажа, иначе — к ближайшей букве пачки. Закрываются, пока пачка дерётся (и герой не стоит в проёме), открываются навсегда, когда пачка мертва. | GDD 10.4 + решение автора 10. |
| D21 | Шлюз затопления убивает мобов в своём прямоугольнике мгновенно и всех, кто зайдёт за 6 с; эссенция за них ×0,5; герою внутри — 40 урона/с. | GDD 13.2, без отдельной анимации набора воды. |
| D22 | Гарпунная стена — «нейтральная» цель: автоатака её не выбирает, бьют только метательный клинок и тап. | Иначе герой залипал бы на стенах во время боя. |
| D23 | Монеты падают с моба (не больше 12 штук, номинал пропорционально) и летят к герою в радиусе подбора. | GDD 12.3; ограничение числа объектов на экране. |
| D24 | Боссы перебалансированы: Грюм — 3600 HP, удар 24 раз в 2,0 с (было 4500 / 40 / 1,6); Мортен — 6500 HP, удар 36 раз в 2,2 с (было 9500 / 60 / 2,0). Навыки и механики — как в GDD. | С числами GDD герою 5-го этажа (≈4–6 карточек) нужно ~56 с на Грюма, а умирает он от обычных ударов за ~25 с даже без промахов по телеграфам — бой невыигрываем. Проверяется ботом в `test_bosses`. |
